3 · Network

Connect your phone.

First make the server address load in the phone's browser. Then configure the Android app with the same reachable address. Examples use port 3265 — replace it everywhere if you chose another.

localhost and 127.0.0.1 mean the device opening the address — on your phone, they mean the phone. 0.0.0.0 is a server listener setting, not a destination.

Choose the address

Where 9t runsAddress to use on the phone
Linux/macOS on the same Wi-FiThat computer's active LAN IP + 9t port
Ubuntu inside Windows/WSL 2Windows' active Wi-Fi/hotspot IP + forwarded port (follow the WSL steps below)
Public serverIts configured https:// domain

Plain LAN hosting in .env.production:

NINE_T_HOST=0.0.0.0
PORT=3265
NINE_T_HTTPS=false

Restart after changes (./9t start, or sudo systemctl restart NAME for a service). Never set NINE_T_HTTPS=false on an existing HTTPS deployment.

Windows with Ubuntu in WSL 2

WSL 2 uses a virtual network: reaching its address from Windows does not prove a phone can reach it. Forward the Windows port into Ubuntu, then connect the phone to Windows' LAN address.

1 · Check 9t in Ubuntu

curl -fsS http://127.0.0.1:3265/api/status
ss -ltnp 'sport = :3265'
hostname -I

Expect {"initialized":true} and a 0.0.0.0:3265 listener. If it shows only 127.0.0.1:3265, fix the binding and restart.

2 · Forward the port in Windows (PowerShell as Administrator)

$distro = "Ubuntu"
$port = 3265
wsl -d $distro hostname -I
# Copy Ubuntu's IPv4 into $wslIp (not the vEthernet (WSL) address):
$wslIp = "172.22.200.10"
netsh interface portproxy add v4tov4 listenaddress=0.0.0.0 listenport=$port connectaddress=$wslIp connectport=$port
netsh interface portproxy show all

3 · Allow it through Windows Firewall (once per port)

New-NetFirewallRule -Name "9t-LAN-$port" -DisplayName "9t LAN TCP $port" -Direction Inbound -Action Allow -Protocol TCP -LocalPort $port -RemoteAddress LocalSubnet -Profile Any

4 · Find the phone-facing address

ipconfig
  • Laptop joined the phone's hotspot → Windows Wi-Fi adapter IPv4.
  • Phone joined the laptop's hotspot → the Windows adapter serving that hotspot (often Local Area Connection*).
  • Both on a router → the laptop's active Wi-Fi/Ethernet IPv4 on that network.

Then open http://<windows-ip>:3265/api/status on the phone, and sign in at http://<windows-ip>:3265.

After a WSL restart, Ubuntu's IP may change — update the existing rule with netsh interface portproxy set …. Remove with netsh interface portproxy delete … + Remove-NetFirewallRule when done hosting.

LAN, hotspots, and internet fallback

  • No internet needed for native LAN transfers once installed and paired — keep the server running, the laptop awake, and the phone on a route to the server. Keep a "no internet" Wi-Fi connection for the LAN test.
  • Some hotspot/guest networks isolate devices — try an ordinary shared Wi-Fi to distinguish isolation from a 9t problem.
  • In Automatic mode, LAN and public URLs must reach the same installation and data directory. The app creates no tunnels and replicates nothing between servers.
