5 · Operations

Keep it running.

Backups, the CLI, the systemd service, and updates. The CLI consumes the same public API as the dashboard — no parallel logic path.

Backups

Systemd timers (install from deploy/systemd/) clean expired and trashed objects hourly and create a daily archive. Fourteen backups are retained by default.

node scripts/restore.mjs backups/9t-….tar.gz --verify

Verify an archive without touching live data. For a real restore: stop 9t first, then omit --verify — the tool keeps the previous data directory beside the restored copy.

CLI commands

From a checkout, link the CLI and authenticate it once (token stored owner-only in ~/.config/9t/config.json; 9t logout revokes it):

npm link
9t login --url https://9t.example.com --username owner
9t push ./photo.jpg
9t push 'docker compose up -d' --name deploy
9t list
9t get ab12cd34
9t share ab12cd34 --lifetime 1d --password optional-password
9t trash ab12cd34
9t restore ab12cd34
9t configure [--section modules|exposure|domain|limits|interface|server]

Service and maintenance scope: 9t setup | start | status | update | doctor, plus 9t config get|set|export|import for edits and migration between installs.

Systemd service

Deployment examples live under deploy/ — adjust user, checkout path, and env-file path before installing. The HTTPS Nginx example is deploy/nginx/9t.conf (Certbot paths assumed).

sudo install -m 644 deploy/systemd/9t.service /etc/systemd/system/9t.service
sudo systemctl daemon-reload
sudo systemctl enable --now 9t.service

Service names for wizard installs are 9t-<checkout-hash>.service so they never overwrite an existing 9t.service. Status and logs: sudo systemctl status NAME, sudo journalctl -u NAME -f.

Update flow

./9t status     # service state, build presence, listener + initialized flag
./9t update      # backup, git pull, rebuild into staging, migrate, restart
  • update refuses on a dirty working tree and backs up data before touching anything.
  • Managed systemd installs restart on the new build automatically (previous build drop-in saved under /tmp); foreground installs print the NINE_T_BUILD_DIR to restart with.
  • After pulling a release with phone-socket support, run npm ci + npm run build and restart — keep the data directory, never rerun setup. The socket lives at /api/mobile/socket on the same port; npm start (not raw next start) serves it.
