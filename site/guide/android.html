Install and pair

  1. Install the signed 9t-android-0.6.1.apk. Android may ask you to allow installation from the app you downloaded it with. Upgrade over the existing install to keep pairing and history.
  2. Easiest — ask from the phone: open the app, tap Find server (or Scan local network on Wi-Fi), name the phone, tap Send connection request. The phone shows a 5-digit session number.
  3. Approve on the web: open Settings → Android devices & pairing (/devices). Check the 5-digit number matches the phone screen, then tap Approve. The phone pairs itself within seconds. Requests expire after 5 minutes.
  4. Alternatively — paste a code: create a pairing code on /devices, paste it into the app. Choose whether to receive existing items (default: new items only).
  5. Start live receiving: allow notifications and accept the Allow background receiving battery prompt (also under Connect). New files save in Downloads/9t. Under Connect, optionally add the server's LAN address; keep Automatic for LAN-first with public fallback.

Pairing codes contain an access key and are shown only once — keep them private, enroll over HTTPS or a trusted local connection, and revoke lost devices from the website (this kills their transfer key and sessions).

Background receiving notes

  • A foreground receiver starts when you open a paired, unpaused app. The notification carries Sync now, Send (inline reply), and Pause. If the socket is unavailable, the receiver falls back to polling.
  • With a LAN address (Automatic or LAN-only) the app uses the connectedDevice service type — no five-hour deadline, sticky, restarts after boot or APK update.
  • Without a LAN address, or Internet-only, the receiver uses dataSync: Android 15+ caps it at six hours per 24 h. The app ends each session after five hours; opening the app can start a new one.
  • Allow background receiving requests the battery-optimization exemption — a notification and wake lock alone do not survive Doze. A JobScheduler job (~every 15 min, deferrable) provides recovery.
  • Force-stop blocks jobs until you reopen the app. OEM battery managers can still delay or stop reception — there is no unconditional always-on promise.
  • Incoming text is copied while unlocked (latest snippet wins; locked-phone copying is deferred). Files queue offline; transfers are AES-256-GCM, chunked and resumable.

If receiving stops when you switch apps: reinstall 0.6.1 over the app, confirm the live-receiving notification survives app switching, grant background receiving, keep the laptop awake, and test the LAN URL in the phone browser. Then use Connect → Receiver details → Copy details to report.
